## 模板的使用限制

### 版本标注不统一

目录名为 `4.954-4.97X`，事件系文件头标为 `4.974`，`New_Api:1` 标为 `4.980`，`CUSTOM_CHECKS:272` 又介绍 `v4.981` 的函数侧接口。目录名和文件头不能作为整套模板的适配证明，应逐接口核对。

### 示例命名仍需核对

`CUSTOM_CHECKS:257` 的示例标签为 `@M_KOJO_CHECK_KX_COM_BLOCKED`，省略了本文件其他多剧本示例使用的 `_XXX`。当前 CHECK 分发器会插入剧本标识符；用于本口上时，应按实际路由核对 `M_KOJO_AME_CHECK_K36_COM_BLOCKED`，不能只替换角色号就认定已接入。

### 注释要与调用上下文共同解释

事件系模板 57 行称 FLAGSETTING 中的角色变量不能省略编号；当前 `KOJO_MESSAGE_SEND` 的 FLAGSETTING 分支在 584 行设置 `TARGET = ARG:2`，600 行调用剧本函数，608 行恢复 TARGET。后续审查应追踪实际入口和函数内的 TARGET 变化，不能仅按模板注释判定本口上的隐式写法有误。

模板还含 `SKIPSTART/SKIPEND`、注释掉的标签及示例专用条件；比对须区分说明、停用片段和实际执行代码。

## 后续比对方法

1. 按功能找对应模板文件和函数，记录模板来源及核验版本。
2. 只在用于比较的文本中归一化角色号、标识符、剧本编号与无意义空白；保留参数、条件、返回值和业务逻辑差异，不修改源文件。
3. 将差异分为模板骨架、用户新增逻辑、可能的接口演变及尚不明确的内容。
4. 回到本体核对动态拼名、调用条件、参数、返回值和状态生命周期；不能因全名搜索不到调用者就判为死代码。
5. 在对应机制条目记载差异及其含义；无相关模板时照常分析源码，不强求每项都有对应模板。

当前本体模板用于理解现行约定；若确需判断历史改动，再查询仓库中可取得的旧版。未确认原始版本时，不使用“从模板删掉了某功能”等历史断言。
