# M006 料理历史结构实装与核验

日期：2026-11-13。用户授权实装8槽、每槽63位的料理历史，随后明确不需要清除旧料理记录，所有测试使用新档。

## 实装结果

- 使用当前角色CFLAG1252～1259，共8槽；每槽只写bit0～62，按料理编号减101后除/余63定位，可表示101～604。
- 移除旧普通三图、固有三图别名和全部业务引用；记录、查询、计数共用新编号规则。
- CASE413继续取得当前成品ID并保留自定义食谱标记，改用新的记录函数；不重排原有SOURCE门控或取得时点。
- 普通料理列表按本体QOL目录筛选；当前183种普通料理全部可列出，包括此前漏掉的14种。标记按ID读取，不随菜单排序移位。
- 固有料理只显示已记录项，实际名称仍通过DISHDATA解析；不会因缺少QOL基础条目而预先排除已记录的口上自定义食谱。
- 料理贡献重新统计普通/固有/自身436号的记录，原1700/174、100、50、其他固有最多4种及各阶段封顶全部保留。
- 测试辅助的原批量99999写入止于1251；料理历史另按当前QOL目录通过记录接口填充，避免将整数99999误写为新料理历史。该工具仍不代表所有回忆来源已经满值，未重做酒或其他数值。

**没有新增清空、转换、迁移、SAVEDATA或FIRSTTIME标记。** 新档使用CFLAG零初值；日初/UPDATE不清空。整角色重置的本体既有1000～1999清零覆盖本区域。本轮没有修改事件系、FIRSTTIME登记或已有初始化函数。

## 源码范围与接口

| 文件 | 本轮改动 |
| --- | --- |
| DIM变量用ERH | 旧六槽别名替换为起点、8块、63位、编号边界及保留编号/自身料理常量 |
| 工具函数ERB | 新增RECORD/HAS/COUNT三个接口；料理贡献接新计数；测试辅助避开旧料理写入 |
| SOURCE相关ERB | CASE413旧大段手写映射替换为新记录接口 |
| 指令ERB | COM299料理页调用按编号显示的公共助手；移除旧顺序/分段读取 |

记录接口只做角色、表示范围和299/400保留编号校验，菜谱有效性前提由原成功制作入口保证；不在记录时再次按名称反查或重新判断材料/制作资格。调用者传角色登记索引，接口核对NO36，既不硬编码角色数组下标为36，也不改变TARGET。

RECORD返回1为新增、0为重复、-1为输入无效；HAS返回0/1；COUNT对请求范围作边界截断并逐位统计，空区间返回0。它们不查数据库、不清记录，也不写额外派生计数。

本机CALLF带参数使用已核验的逗号形式。CASE413使用CALLF丢弃记录返回值，避免覆盖先前料理ID/自定义分支结果。

## 本机隔离引擎核验

2026-11-14补充：原脚本已接入经过18项可靠性检查的共享执行/判定模块，加入当次运行标识、源码/输入/引擎指纹、退出码和日志诊断约束后，原2093项断言再次0失败。最新结果文件含独立运行目录和归档清单；2026-11-13原结果已另存，见[可靠性核验与使用说明](隔离引擎测试可靠性核验.md)。本轮没有修改业务源码或扩大原覆盖范围。

使用本机同一版本`Emuera.NET SkiaSharp 1824+v24+EMv18+EEv56+Skiav10.1`的可执行文件副本，在项目tmp目录内构造新角色数据。没有启动正常游戏目录、没有加载/修改用户存档，也没有调用本体QOL初始化或写数据库。

将当前生产源码中的RECORD、HAS、COUNT、料理贡献、阶段读取、显示助手及修改后的测试辅助原样抽取到隔离环境执行。QOL存在性查询使用当前只读缓存ID快照，DISHDATA用测试名称替代，因此不把它算作实际食谱解析/完整菜单联调。

**最终结果：2093项断言，0失败；引擎正常退出码0。**

覆盖：

1. 新数据初始零值、首次/重复记录、相邻记录独立。
2. bit62与下一块bit0、首末编号、全部504个可表示位置及保留编号排除；每个块符号位始终为0。
3. 负编号、越界编号、无效角色、非NO36角色拒绝；左右相邻槽和角色37数据不受影响。
4. TARGET保持，CALLF调用不覆盖原RESULT。
5. 当前342个目录ID逐项写入/重复/读取，统计183普通、159固有；区间截断、反向空区间。
6. 自身料理不重复算作其他固有；空记录、自身100、另一种固有加50、普通整数贡献，以及0～4阶段封顶。
7. 显示助手筛选183普通/159已记录固有；反向范围为空；无QOL条目的已记录自定义样本仍可进入解析显示路径。
8. 修改后的测试辅助可在表达式函数内调用记录接口，填入当前目录且保留已有自定义样本，不写旧料理整数位图。
